What it is

Static analysis that reads the package like an attacker.

Extensya strips the CRX header in memory, inventories the ZIP payload, and scans every JavaScript, HTML, JSON and support file with comments masked. It explains what the extension can do, how sensitive values move through the code, and which known malicious behaviours the package implements.

It is built for analysts, store reviewers, incident responders, malware researchers and anyone who wants a second opinion on a .crx or .xpi before installing it. The output is a deterministic report: permissions, findings, chains, decoded payloads, signatures, MITRE techniques, IOCs and hashes, ready to export as JSON or as a black-theme PDF.

Extensya is not a sandbox. It never installs the extension, never executes its scripts and never opens it in a browser profile. It reads bytes and reasons about them. A clean verdict means nothing suspicious was visible to static analysis, not that the package is safe.

Toolbox

Every angle on the package.

One report connects the manifest, the code, the hidden layers and the behaviour.

01

Package intake

Open .crx, .xpi, .zip, .nex or .jar, drop an unpacked folder, paste a 32-character Chrome extension ID, or paste a Chrome Web Store, Firefox AMO, Edge Add-ons or Opera add-ons listing URL. CRX2/CRX3 headers are stripped in memory.

CRXXPIfolderstore URL
02

Manifest intelligence

Every declared permission is graded per API: cookies, debugger, proxy, native messaging, clipboard, history, management, identity, webRequest, scripting, tabs and more. Host access, content-script matches, all_frames, externally connectable origins, CSP, update URLs and MV2 vs MV3 are all audited.

03

Rule-based code scanning

59 rules look for remote code, eval and new Function, eval(atob(...)), remote script imports, executeScript({code}), obfuscation, packers, anti-debug statements, reversed endpoints, webhooks, Telegram bots, .onion services, bare-IP endpoints and dangerous API combinations.

59 rulescomments maskedcombinations
04

Source-to-sink attack chains

A data-flow pass traces cookies, password fields, keystrokes, clipboard data, history, tabs, identity tokens, storage, location, camera, screenshots, page content and decoded payloads into network, execution, injection, download and cookie-write sinks. A password manager that reads a field and never sends it is separated from a stealer.

19 sources14 sinksendpointconfidence
05

Hidden payload decoding

Recursive static decoding of Base64, hex, URL escapes, Unicode escapes, character codes, reversed strings, Dean Edwards packers and obfuscator string arrays, up to four layers deep. Every layer keeps its provenance, is re-scanned with the normal rules, and yields IOCs and MITRE techniques.

06

Threat signatures

22 curated cross-file behaviour signatures: session stealing, credential harvesting, keylogging, crypto clipping, remote loaders, update hijacking, ad injection, cookie stuffing, search hijacking, proxyware, cryptomining, data brokering, extension tampering, native shell bridges, wallet draining, obfuscated execution, hidden infostealers, anti-analysis and more.

07

MITRE ATT&CK & IOCs

Every technique emitted by a signature, attack chain or decoded payload is grouped by tactic in the Threats tab. The IOC inventory deduplicates endpoints, webhooks, raw-IP URLs, Tor services, wallets, tokens and secrets, and sends any indicator to the Decoder with one click.

08

Source workbench

A full-window code review with a file rail, syntax highlighting, gutter markers, find, wrap, copy, save, inline editing and per-file heuristics. It reports entropy, endpoints, a local risk score and the scan findings that point into the file. Beautify formats JS, TS, JSON, CSS, HTML, Python and more without executing anything.

Decoder & AI second opinion

A local transform workbench for Base64, URL, hex, HTML entities, ROT13, binary, octal, Unicode, JWT, case, reverse, URL extraction, hashes and format identification. Optionally ask OpenRouter, DeepSeek, local Ollama/LM Studio or any OpenAI-compatible model to review the static evidence as untrusted data.

    Get the binary

    Download the Linux x86-64 release above, or copy the curl command. The build carries the package reader, scanner, payload decoder, chain engine, signature engine and desktop UI.

    Install the desktop stack

Local by design

Your samples stay on your machine.

Extensya runs offline and locally. There is no account, no telemetry and no cloud backend. Packages are read from disk or downloaded into memory, and nothing is installed or executed. The only network traffic is the store download you explicitly request and the optional AI review you explicitly run.

URL scans download the current version over HTTPS with a 64 MB cap, so the store sees a request from this machine. Rescan to check a newer build. The static rules stay the evidence of record; an AI verdict is a second opinion, not proof.

Read-only by construction: CRX headers are stripped in memory, ZIP entries are inventoried in memory, comments are masked before matching, and decoded payloads are inspected as text.

No cloud

No hosted service, no account and no telemetry. Reports and settings stay under your control.
